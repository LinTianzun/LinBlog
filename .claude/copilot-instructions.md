# LinBlog 项目开发指令

## 项目状态

LinBlog 仍处于开发阶段。部分功能、接口联调和数据库行为可能尚未完成或验证。

任何功能是否完成，都必须依据当前代码、测试结果和文档判断，不得根据目录名称、注释或历史描述直接认定。

## 项目结构

* `lin_blog/`：Vue 前端项目。
* `serve/`：Node.js / Express 后端项目。
* `Documentation/`：项目文档和开发进度。
* `README.md`：项目入口说明。

已知技术栈包括 Vue 3、TypeScript、Vite、Pinia、Vue Router、WangEditor、ECharts、Yike UI、Express、MySQL、JWT 和 bcrypt。修改前应检查实际依赖和版本。

已知后端入口为 `serve/linlog.js`，数据库初始化文件为 `serve/model/db/dbnew.js`。

## 通用开发规范

1. 先阅读相关代码和文档，再决定如何修改。
2. 优先复用现有实现，保持当前架构与代码风格。
3. 只修改任务相关文件，避免无关重构。
4. 修改前检查 Git 状态和已有差异，不覆盖用户未提交的工作。
5. 不虚构 API、数据表、脚本、测试结果或项目现状。
6. 如果存在多种方案，优先选择改动小、风险低、容易验证的方案。
7. 变更涉及重要业务规则、数据结构或兼容性时，先说明影响；关键信息不明确时向用户确认。
8. 默认使用简体中文沟通和编写开发文档。

## 前后端协作

* 前端请求必须与实际后端路由、请求参数、响应结构和认证方式一致。
* 新增或修改接口时，同时检查调用方和被调用方。
* 不通过硬编码假数据掩盖真实接口失败。
* 如果项目已有 Mock 数据或 MockJS，明确区分模拟数据和真实接口数据。
* 修改认证、用户信息、文章权限等逻辑时，检查前后端权限是否一致。

## 依赖与配置

* 优先使用项目已安装的依赖。
* 新增依赖前先说明必要性，避免重复实现已有能力。
* 不将密码、令牌、数据库凭据等敏感信息写入源码。
* 不随意覆盖 `.env`、锁文件或其他本地配置。
* 运行命令前先查看对应 `package.json` 中的脚本，不要猜测脚本名称。

## 数据库与安全

* 数据库结构和初始化逻辑必须以现有 SQL、模型和代码为依据。
* 默认禁止重置、清空、删除数据库或业务表。
* 涉及数据迁移、批量更新和删除操作时，先说明影响并等待用户明确授权。
* 使用参数化 SQL，正确处理异常和输入校验。
* 不记录密码、令牌或完整敏感数据。

## 验证与交付

完成修改后：

1. 检查实际代码差异。
2. 执行与变更相关且可运行的检查。
3. 报告实际执行的命令和结果。
4. 明确列出未执行的检查及原因。
5. 更新 `Documentation/开发进度.md` 中相关事项。

只有得到相应验证证据后，才能将功能标记为已完成。不能运行的测试必须标记为待验证，而不是默认通过。

## 高风险操作

没有明确授权时，不得执行破坏性 Git 操作、清空数据库、批量删除文件、强制覆盖用户修改或向远程仓库推送提交。

任何可能导致不可逆变更的操作，都应先向用户说明影响并取得同意。
