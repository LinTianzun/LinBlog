# 内容创作工作流

文章与摄影图库的编辑页现在是一套完整的长文写作流程：**自动保存**、
**发布前预览**、**定时发布**、**待发布工作台**、**版本历史与回滚**。

核心设计只有一句话：**已发布内容与编辑工作稿分离**。
自动保存只写工作稿，读者看到的线上正文不会被改动，直到作者主动发布。

---

## 1. 数据模型

迁移 `20261030_article_workflow` 在 `article` 表新增工作稿字段，
并新建 `article_version` 快照表。

### `article` 新增字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `scheduled_at` | `DATETIME` | 计划发布时间，NULL 表示未安排 |
| `draft_content` | `LONGTEXT` | 已发布内容的工作稿正文 |
| `draft_payload` | `LONGTEXT` | 工作稿元数据 JSON：标题、分类、标签、简介、封面 |
| `draft_revision` | `INT UNSIGNED` | 工作稿修订号，自增，作为乐观锁 |
| `draft_saved_at` | `DATETIME` | 最近一次工作稿保存时间 |

索引 `idx_article_scheduled (state, scheduled_at)` 支撑定时发布扫描。

### `article_version` 快照表

快照按来源分级保留，避免重度写作时自动保存把 `LONGTEXT` 快照表迅速撑大：

| 来源 | 保留策略 |
| --- | --- |
| `autosave` | 5 分钟窗口内只留首条；超过 **24 小时**或超出最近 **50** 条后自动清理 |
| `manual` / `publish` / `rollback` / `scheduled` | 代表明确操作节点，长期保留，不参与自动清理 |

| 字段 | 说明 |
| --- | --- |
| `article_id` + `revision` | 唯一键，修订号单调递增 |
| `title` / `subset_id` / `classify` / `label` / `introduce` / `content` / `cover` | 快照内容 |
| `state` | 快照时的发布状态 |
| `source` | `manual` / `autosave` / `publish` / `rollback` / `scheduled` |
| `created_by` / `created_at` | 操作者与时间 |

## 2. 工作稿语义

| 内容状态 | 自动保存写到哪里 | 发布时发生什么 |
| --- | --- | --- |
| 草稿 / 已驳回 | 直接更新 `article` 正式字段 | 只需切换状态，工作稿即线上内容 |
| 已发布 | 只写 `draft_content` + `draft_payload` | 把工作稿写回正式字段并清空工作稿 |

这样「自动保存」永远不会把半成品推给读者，也不需要额外的草稿表。

### 快照体积治理

每次自动保存都会推进 `draft_revision` 并更新工作稿字段，但不再无条件
写入一条完整 `LONGTEXT` 快照：

- 写入前先看最新一条快照，如果它也是 `autosave` 且落在 **5 分钟**内，
  本次只更新工作稿、不新增快照，即「按 5 分钟合并」；
- 手动保存、发布、回滚、定时发布始终各留一条独立快照，不受合并影响；
- 每次保存顺带清理超过 **24 小时**的自动快照，并把自动快照收敛到最近 **50** 条；
- 两类清理都带 `source = 'autosave'`，明确操作节点不会被高频自动保存挤掉。

`draft_revision` 逐次递增，防丢稿与乐观锁语义不变；版本面板里的自动快照
会按写作节奏自然收敛。

**状态流转时会提升工作稿**：`撤回`（已发布 → 草稿）和 `草稿 → 发布`
都会把工作稿落到线上字段并清空，避免未发布的修改丢失，
也避免下次进入编辑页时旧工作稿被误当成「未发布修改」弹回来。

## 3. 接口

所有接口都带 `/api/article/:id` 前缀，文章与图库共用一套，
权限按内容真实 `classify` 选择 `article.*` 或 `gallery.*` 前缀。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/article/scheduled` | 待发布工作台队列，支持 `classify=article\|image`，回传即将发布与逾期统计 |
| `GET` | `/api/article/:id/workflow` | 读取当前工作稿、修订号、计划发布时间 |
| `POST` | `/api/article/:id/workflow/draft` | 保存工作稿，携带 `revision` 做乐观锁；冲突返回 409 |
| `GET` | `/api/article/:id/versions` | 版本列表，支持 `page` / `pageSize` |
| `GET` | `/api/article/:id/versions/:versionId` | 版本详情 |
| `POST` | `/api/article/:id/versions/:versionId/restore` | 回滚：恢复为**新的**工作稿，不覆盖历史 |
| `POST` | `/api/article/:id/workflow/publish` | 发布当前工作稿 |
| `POST` | `/api/article/:id/workflow/schedule` | 安排定时发布（至少晚于当前 1 分钟） |
| `DELETE` | `/api/article/:id/workflow/schedule` | 取消定时发布 |

### 乐观锁

保存时传入 `revision`（来自 `GET /workflow`）。若服务器上的修订号已变化，
接口返回 `409` 与最新 `revision`，前端提示「工作稿已在其他窗口更新」，
避免两个窗口互相覆盖。

冲突不再是「只能整页重载」：点击保存状态旁的「对比修改」会打开
**三方对比弹窗**（`ConflictCompareDialog.vue`，对比逻辑在
`lin_blog/src/utils/conflictCompare.ts`）：

- **共同基线**：本窗口加载（或最近一次保存成功）时的快照 `lastSavedSnapshot`；
- **本窗口**：当前编辑器内容；**对方**：重新拉取的服务器工作稿；
- 字段级对比列出标题、标签、摘要、封面、分类与正文/图片，仅显示有改动的行，
  双方都改且值不同的行标记「双方都修改」，双方改成相同值不算冲突；
- 文章正文给出相对共同基线的行级 diff（对方与本窗口两列，超长正文降级为
  整段替换），图库则列出对方新增/删除的图片缩略图；
- 「采用对方版本」丢弃本窗口修改并重新加载最新工作稿；
  「保留我的修改并覆盖」携带弹窗里的对方修订号重新提交，成功后本窗口
  成为最新修订；若提交时对方又抢先保存（再次 409），弹窗会自动重新拉取
  并展示最新差异，不会静默覆盖；
- 冲突弹窗打开期间暂停自动保存，避免反复撞 409。

### 回滚语义

回滚不是「覆盖历史」，而是把目标版本内容恢复成**新的工作稿**，
再追加一条 `source=rollback` 的快照。因此版本链只追加、不篡改，
回滚之后仍然可以再回到回滚前的版本。

## 4. 定时发布

`serve/utils/articleScheduler.js` 每 **30 秒**扫描一次
`scheduled_at IS NOT NULL AND scheduled_at <= NOW()` 的内容。

- 更新语句带 `scheduled_at IS NOT NULL` 条件，多实例同时运行时不会重复发布；
- 到点后先应用工作稿，再置为 `published` 并清空计划时间；
- 每次执行写系统日志（`定时发布已执行`）。
- 同一条内容持续发布失败时只写一次失败告警；成功发布或取消计划后会重置告警状态；
- 服务启动时立即扫描一次，之后按间隔轮询；进程退出时优雅停止。

### 待发布工作台

后台侧栏「内容 → 定时发布」对应 `/scheduledPublish`，进入条件是拥有
`article.publish` 或 `gallery.publish` 中任意一项。接口不会只凭发布权
返回全站数据：文章队列要求 `article.manageAll` 或 `article.manageOwn`，
图库队列同理使用 `gallery.*`，普通作者只能看到自己的内容。

- 队列按计划时间升序排列，页面按日期块展示，可切换全部/博客文章/摄影图库；
- `scheduled_at <= NOW()` 且仍未发布的内容标记为「逾期」，不会额外写失败状态；
- 「改期」复用安排定时发布接口，「立即发布」应用当前工作稿，「取消计划」只清计划；
- 待发布总数、即将发布、已到点未发布三项统计始终基于当前筛选和作用域；
- 页面可见时每 30 秒静默刷新，操作进行中暂停自动刷新，离开页面会清理定时器。

## 5. 前端交互

文章页 `lin_blog/src/views/EditArticle.vue` 与图库页
`lin_blog/src/views/EditGallery.vue` 使用同一套逻辑：

- 顶部显示状态标签、「有未发布修改」标记与保存状态文案；
- 停止输入 **1.5 秒**后自动保存；页面关闭前若有未保存修改会提示；
- 保存冲突（409）时出现「对比修改」入口，弹窗展示三方对比并可
  采用对方版本或保留本窗口修改覆盖保存；
- 「预览」弹窗展示当前编辑内容（正文经 DOMPurify 清洗，图片按需优化）；
- 「版本历史」面板可查看、翻页、查看详情与回滚；
- 「定时发布」下拉可安排或取消计划发布时间；
- 侧栏「定时发布」工作台可集中处理待发布队列、逾期告警与改期/发布/取消操作；
- 图库预览展示图片墙，版本面板显示「N 张图片」。

### 新建页的本机草稿

新建时还没有后端 ID，无法调用工作稿接口。因此新建文章 / 图库会把内容
先写入 `localStorage`（键为 `linblog.local-draft.article-new` /
`linblog.local-draft.gallery-new`），刷新、崩溃或误关标签页后重新进入
会提示恢复；创建成功后自动清除，也可以手动「丢弃本机草稿」。

### 列表可见性

文章与图库列表接口回传 `hasUnpublishedChanges`（是否存在未上线工作稿）
和 `scheduledAt`（计划发布时间），卡片直接显示「有未发布修改」与
「定时发布」角标，不必进编辑页才能发现。
